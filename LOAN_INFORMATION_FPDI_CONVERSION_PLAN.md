## 1. Architecture recap (confirmed)

Loan Information is generated by `LoanInformationPdfService`
(`app/Services/LoanRequests/LoanInformationPdfService.php`, 130 lines): Blade view
`resources/views/reports/loan-information.blade.php` → Browsershot/Chromium (`paperSize(8.5,13,'in')`)
with a DomPDF fallback (`setPaper([0,0,612,936],'portrait')`) when `config('reports.pdf_driver') !==
'chromium'`.

The FPDI target, `ApprovedLoanPdfTemplateService::renderTemplateBytes()`
(`app/Services/LoanRequests/ApprovedLoanPdfTemplateService.php:112`), is **fully page-size-agnostic
already** — it calls `$pdf->getTemplateSize($templateId)` per page and calls `AddPage($orientation,
[$pageSize['width'], $pageSize['height']])` with whatever size the base PDF's own MediaBox declares
(`makePdf()` at line 585 just seeds a placeholder `'A4'` format that gets overridden immediately).
**No changes are needed to the engine to support this document's larger page size.** Confirms sub-ask 4
from the original investigation.

`renderField()` (line 170) dispatches on `field['type']`: `'check'` → `renderCheckField()`, `'image'` →
`renderImageField()`, anything else (default `'text'`) → the text path, with `shrink_to_fit`/`width`
variants. The `'image'` type (used for AU's header-logo box, see
`AffidavitUndertakingPdfFieldMap::fields()` entry #1) is **generic and directly reusable unmodified** —
confirms sub-ask 4 fully: no per-document image-handling code exists to duplicate or adapt.

Dispatch wiring lives in `ApprovedLoanDocumentService`
(`app/Services/LoanRequests/ApprovedLoanDocumentService.php`) at call sites that must change:
- `loanInformation()` — currently `$this->loanInformationPdfService->generate($outputPath, $documentData)`.
- `packageZip()` — same call, inside the full-package ZIP assembly.
- **Correction (2026-07-19, found during Phase 1 implementation):** a **third** call site exists
  that this investigation missed — `generateToPathForKey()`'s `match ($documentKey)` arm for
  `LoanRequestDocumentKey::LoanInformation`, used by `LoanRequestDocumentWorkflowService` (the
  workflow-driven regeneration path, e.g. manager approval) and covered by
  `LoanRequestGenerateDocumentsBulkTest.php`. All three call sites were updated in Phase 1; anyone
  auditing this plan against the code should not assume "two call sites" is exhaustive.

Both must become `$this->approvedLoanPdfTemplateService->generate(self::PDF_TEMPLATE_FILENAMES['loan_information'], $outputPath, $documentData, $this->loanInformationPdfFieldMap)`,
matching the AU/Authorization pattern exactly (see lines 190–198, 200–215 for the reference shape).

Additional wiring required:
- Add `'loan_information' => 'loan information sheet.pdf'` to `PDF_TEMPLATE_FILENAMES` (line 43–48;
  note the literal filename has a space, matching the file on disk — `resolveTemplatePath()` in
  `ApprovedLoanPdfTemplateService` reads under `TEMPLATE_DIRECTORY =
  'templates/approved-loan-documents/pdf'` relative to `storage/app`, so no directory change needed).
- Add `use App\Services\LoanRequests\PdfFieldMaps\LoanInformationPdfFieldMap;` import and constructor
  property (alongside `affidavitUndertakingPdfFieldMap`/`authorizationPdfFieldMap`, lines 94–95).
- `$this->loanInformationPdfService` (line 98) becomes unused by both call sites once switched — see
  §6 for its disposal decision.

  matching the established AU/Authorization/UB pattern.

## 9. Phase 2 completion notes (2026-07-19)

Phase 2 is complete. This environment has no PDF rasterizer installed (no `pdftoppm`/Ghostscript/
ImageMagick), so true visual calibration looked out of reach at first — worked around it by using
this project's own Puppeteer/Chromium dependency (already present for Browsershot) to open the
generated PDF in headless Chromium's built-in PDF.js viewer and screenshot it, giving an actual
rendered image to inspect rather than relying on "no exceptions thrown" or text-extraction proxies.
Rendered against the **real production artwork** (not a synthetic template) with representative and
stress-test (long-name/long-address/large-amount) data.

**Finding — systematic vertical misalignment, now fixed.** Every stamped value sat visibly below its
baked-in label. Root cause: TCPDF's `Text()`/`MultiCell()` (used by `writeText()`/
